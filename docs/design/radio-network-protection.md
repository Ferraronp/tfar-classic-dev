# Дизайн радиосовместимости и защиты сети

Статус: **предлагается к утверждению**

Связанная задача: [#9](https://github.com/Ferraronp/tfar-classic-dev/issues/9)

Зависимость следующего этапа: versioned protocol/capabilities между Arma и TeamSpeak-плагином

## 1. Результат дизайна

Новая модель отделяет физический радиоканал от игровой защиты содержимого:

```text
radio route = waveform + frequencyKHz + protectionCode + talkGroup
```

Решения для MVP:

| Вопрос | Решение |
| --- | --- |
| Где хранится код | На каждом канале конкретного экземпляра рации |
| Формат кода | Строка из трёх цифр; `000` означает открытую сеть |
| Совместимость моделей | Определяется возможностями устройства, а не classname или стороной |
| КВ ↔ ДВ | Разрешена в общей части диапазона при одинаковом waveform и сетевых параметрах |
| Захват рации | Даёт все сохранённые частоты и коды этого экземпляра; их можно перенести на совместимую рацию |
| Режим старых миссий | `Legacy`, включён по умолчанию и сохраняет текущее поведение побитно на уровне route key |
| Новые режимы | `Open` игнорирует код; `Keyed` требует точного совпадения кода |
| Talk Group | Поле резервируется в протоколе сразу, но до #10 всегда равно `0` |
| Реальная криптография | Не моделируется; код является правилом маршрутизации игрового аудио |

`tf_subtype` остаётся выбором DSP/звука (`digital`, `digital_lr`, `airborne`, `dd`) и не используется как скрытая метка совместимости.

## 2. Термины и границы

- **Экземпляр рации** — конкретная instanced SW-рация либо конкретная LR-рация в объекте рюкзака/транспорта.
- **Возможности устройства** — поддерживаемые waveform, минимальная и максимальная частота, шаг сетки и дальность передачи.
- **Маршрут канала** — активные `waveform`, нормализованная частота, protection code и talk group.
- **Protection code** — игровая метка доступа к содержимому. Это не ключ шифрования и не защита данных TeamSpeak.
- **Открытая сеть** — канал с кодом `000` в `Keyed` либо любой канал в режиме `Open`.

В MVP не входят:

- hopping, COMSEC-ключи, key fill devices и удалённое обнуление;
- сканирование эфира, подбор кода и перехват зашумлённого аудио;
- радиопомехи, коллизии одновременных передач и подавление;
- cross-band relay и автоматические мосты между сетями;
- Talk Groups, кроме зарезервированного значения `0`;
- изменение DSP Classic.

## 3. Финальное правило «услышит / не услышит»

Для `Open` и `Keyed` передача слышна тогда и только тогда, когда одновременно выполнены все условия:

1. Передатчик и приёмник имеют совместимую версию протокола.
2. Оба устройства поддерживают waveform активного маршрута.
3. Нормализованная частота попадает в диапазон и сетку обоих устройств.
4. `waveform` и `frequencyKHz` совпадают.
5. Режим защиты допускает пару кодов.
6. `talkGroup` совпадает; до #10 у обеих сторон это `0`.
7. Существующие проверки TFAR разрешают передачу: рация доступна, среда подходит, передатчик в радиусе с учётом его мощности/антенны и остальные ограничения Classic выполнены.

Формально:

```text
heard = protocolCompatible
     && txCapabilities.accept(tx.route)
     && rxCapabilities.accept(tx.route)
     && waveformEqual
     && frequencyEqual
     && protectionCompatible(mode, tx.code, rx.code)
     && talkGroupEqual
     && propagationAllows(tx, rx)
```

Правило защиты:

```text
Legacy: старое точное совпадение строки frequency + legacyRadioCode
Open:   protectionCode не участвует в сравнении
Keyed:  tx.protectionCode == rx.protectionCode
```

В `Keyed` код `000` совпадает только с `000`. Приёмник на `123` не слышит открытую передачу, а открытый приёмник не декодирует передачу `123`.

### 3.1 Нормализация частоты

В v2-протоколе частота передаётся целым числом килогерц. Например, `50`, `50.0` и `50.000` превращаются в `50000` и считаются одним физическим каналом. Это устраняет зависимость маршрутизации от строкового представления числа.

Ввод в UI остаётся в МГц. Значение принимается только тогда, когда оно попадает в диапазон устройства и на его сетку частот.

### 3.2 Возможности штатных устройств

Значения ниже сохраняют существующие ограничения Classic и допускают связь КВ ↔ ДВ в пересечении диапазонов.

| Семейство | Waveform по умолчанию | Диапазон | Шаг | Особенность |
| --- | --- | ---: | ---: | --- |
| Обычная КВ (SW) | `tfar_fm_voice` | 30–512 МГц | 100 кГц | Дальность берётся из `tf_range` конкретной модели |
| LR-рюкзак | `tfar_fm_voice` | 30–87 МГц | 100 кГц | Не является отдельным несовместимым видом сигнала |
| Транспортная LR | `tfar_fm_voice` | 30–87 МГц | 100 кГц | Настройки принадлежат qualifier конкретного транспорта |
| Airborne LR | `tfar_fm_voice` | 30–87 МГц | 100 кГц | `airborne` продолжает влиять только на DSP и дальность |
| Подводная DD | `tfar_dd` | 32–41 МГц | 100 кГц | В первом срезе остаётся на существующем отдельном пути |

Новые config-свойства устройства:

```text
tf_waveform = "tfar_fm_voice";
tf_frequencyMin = 30;
tf_frequencyMax = 512;
tf_frequencyStepKhz = 100;
```

Для старых аддонов применяются fallback-значения по типу SW/LR/DD. Мод может явно объявить другой waveform или более узкий диапазон. Совпадение classname никогда не является отдельным условием.

## 4. Матрица совместимости

Во всех строках ниже предполагается, что обычные проверки доступности рации и физической дальности пройдены, если не указано обратное.

| Режим | Передатчик | Приёмник | Результат | Причина |
| --- | --- | --- | --- | --- |
| Legacy | `100.0_bluefor` | `100.0_bluefor` | Слышит | Точное старое совпадение |
| Legacy | `100.0_bluefor` | `100.0_opfor` | Не слышит | Старые radio code различаются |
| Open | SW, 50 МГц, `tfar_fm_voice` | LR, 50 МГц, `tfar_fm_voice` | Слышит | Частота лежит в обоих диапазонах; код игнорируется |
| Open | SW, 100 МГц | LR с максимумом 87 МГц | Не слышит | Приёмник не поддерживает частоту |
| Open | 50 МГц, `tfar_fm_voice` | 50 МГц, `other_waveform` | Не слышит | Несовместимый waveform |
| Keyed | разные classname, 50 МГц, код `123` | 50 МГц, код `123` | Слышит | Корпус и сторона не участвуют в сравнении |
| Keyed | SW, 50 МГц, код `123` | LR, 50 МГц, код `123` | Слышит | Совпали route и возможности |
| Keyed | 50 МГц, код `123` | 50 МГц, код `124` | Не слышит | `code_mismatch` |
| Keyed | 50 МГц, код `000` | 50 МГц, код `000` | Слышит | Открытая сеть |
| Keyed | 50 МГц, код `000` | 50 МГц, код `123` | Не слышит | Открытая и защищённая сети различаются |
| Keyed | одинаковый route | одинаковый route, но вне эффективной дальности | Не слышит | `out_of_range` после успешного route match |
| Keyed | terrestrial SW | DD на той же числовой частоте | Не слышит | `waveform_mismatch` и несовместимая среда |
| Keyed | основной канал `123` | additional channel `123` на той же частоте | Слышит | Additional channel использует настройки своего channel slot |
| Keyed | TG `0` | TG `1` после реализации #10 | Не слышит | `talk_group_mismatch` |

Плагин должен уметь записать одну причину отказа из фиксированного набора: `protocol_mismatch`, `waveform_mismatch`, `frequency_mismatch`, `tx_out_of_band`, `rx_out_of_band`, `code_mismatch`, `talk_group_mismatch`, `medium_mismatch`, `out_of_range`.

## 5. Хранение настроек

### 5.1 Код относится к channel slot

Protection code хранится на канале, а не одним значением на всю сторону и не в глобальном key set. Переключение канала атомарно меняет частоту и код. Additional channel читает код того channel slot, на который он указывает.

Массивы settings расширяются только в конце, чтобы существующие индексы не сдвигались:

```text
SW: [active, volume, frequencies[], stereo, legacyCode,
     additional, additionalStereo, owner, speaker,
     protectionCodes[], talkGroups[], schemaVersion]

LR: [active, volume, frequencies[], stereo, legacyCode,
     additional, additionalStereo, speaker, nil,
     protectionCodes[], talkGroups[], schemaVersion]
```

Предлагаемые общие offsets:

```text
TF_PROTECTION_CODES_OFFSET = 9
TF_TALK_GROUPS_OFFSET       = 10
TF_SETTINGS_SCHEMA_OFFSET   = 11
TF_SETTINGS_SCHEMA_VERSION  = 2
```

`legacyCode` на offset 4 не удаляется. В `Legacy` он остаётся источником старого route key. В новых режимах используются только новые per-channel массивы.

### 5.2 Привязка к экземпляру

- Для SW используется существующее instanced classname и его `<radio>_settings` в `missionNamespace`.
- Для LR используется существующая переменная qualifier на объекте рюкзака/транспорта.
- Копирование loadout создаёт независимый экземпляр с копией настроек на момент операции. Последующие изменения одной рации не должны менять другую.
- Drop/pickup и передача предмета сохраняют settings самого экземпляра.
- Копирование network tuple между двумя рациями не связывает их settings ссылкой.

Это продолжает исправленную в #14 модель владения SW-рациями и не вводит второй реестр идентичности.

### 5.3 API

Новые функции должны явно принимать channel slot:

```text
getSwProtectionCode(radio, channel)
setSwProtectionCode(radio, channel, code)
getLrProtectionCode(radio, channel)
setLrProtectionCode(radio, channel, code)
getRadioRoute(radio, channel)
canProgramRadioRoute(source, target, channel)
copyRadioRoute(source, sourceChannel, target, targetChannel)
```

Старые `get/setSwRadioCode` и `get/setLrRadioCode` остаются compatibility wrappers:

| Режим | Старый getter | Старый setter |
| --- | --- | --- |
| Legacy | Без изменений | Без изменений |
| Open | Возвращает пустую строку | Игнорируется с однократным warning |
| Keyed | Код активного канала | Меняет код активного канала и пишет deprecation warning |

## 6. Режимы миссии и значения кода

Серверно-принудительная настройка `TFAR_radioNetworkMode`:

| Значение | Поведение |
| --- | --- |
| `Legacy` | Текущая строка `frequency + radioCode`; старые addon/plugin совместимы |
| `Open` | v2 route; protection code нормализуется в `000` и не сравнивается |
| `Keyed` | v2 route; требуется точное совпадение `000..999` |

Значение по умолчанию — `Legacy`. Миссия должна явно включить новый режим.

Дополнительные серверные настройки:

- `TFAR_allowProtectionCodeProgramming` — разрешить игроку менять код через UI; по умолчанию `true` в `Keyed`;
- `TFAR_allowOpenProtectionCode` — разрешить ввод `000`; по умолчанию `true`;
- `TFAR_legacyProtectionCodeMap` — явное отображение старых code strings в трёхзначные значения при миграции;
- per-side defaults для новых раций: West `100`, East `200`, Independent `300`, Civilian `000`.

Режим и запреты публикует сервер. Они не являются защитой от модифицированного клиента, но обычный клиент не может ослабить политику локальной CBA-галочкой.

### 6.1 Валидация

- Допустимы только ASCII-строки по regex `^[0-9]{3}$`.
- Ведущие нули сохраняются.
- `000` имеет единственное специальное значение OPEN.
- Пустая, короткая, длинная или нечисловая строка не применяется.
- Запрещённое миссией `000` не заменяется другим кодом молча.
- Некорректная настройка блокирует route и даёт понятный hint/RPT warning; fallback в открытую сеть запрещён.

## 7. Захват и программирование чужой рации

При захвате игрок получает состояние самого экземпляра:

- все channel frequencies;
- protection code каждого канала;
- Talk Group каждого канала после #10;
- active/additional channel, volume, stereo и speaker state как сейчас;
- аппаратные возможности из classname/config.

Игрок не получает глобальный список кодов стороны, настройки других раций или скрытый серверный key set — такого key set в MVP нет.

UI позволяет:

1. Открыть захваченную рацию и прочитать `NET 000`/`NET 123` выбранного канала.
2. Вручную ввести частоту и код на собственной рации.
3. Через действие `Copy network` перенести только `frequency + protectionCode + talkGroup` выбранного канала на выбранный канал другой рации.

`Copy network` не переносит owner, volume, stereo, active channel или весь preset bank. Операция доступна только для двух физически доступных игроку раций и заранее проверяет waveform, диапазон и шаг target-устройства. При несовместимости она ничего не меняет и показывает точную причину.

Если миссия запретила программирование, захваченная рация сохраняет свои настройки и работает как есть, но штатный UI не меняет свою или другую рацию.

## 8. Рюкзаки, транспорт, speakers и relay

- LR-рюкзак и транспортная LR участвуют в том же route match, что SW.
- Настройки рюкзака сохраняются на его объекте; захват рюкзака захватывает его preset bank.
- Внешний TX через рюкзак радиста из #8 обязан использовать route рюкзака, а не личной рации говорящего.
- Speaker не создаёт новую сеть: он воспроизводит только передачу с route, совпавшим у включённой speaker-рации.
- `SPEAKERS` v2 передаёт структурированный route, а не старую склеенную строку.

Автоматического ретранслятора в MVP нет. Будущий relay моделируется двумя независимыми legs: RX route и TX route. По умолчанию он не мостит разные waveform/code/TG и не снимает protection code. Явный cross-network bridge должен быть отдельной mission-authorized функцией с защитой от циклов.

## 9. Versioned protocol

### 9.1 Negotiation

Перед первым v2 `FREQ` addon выполняет локальный handshake:

```text
PROTOCOL\t2\tradio_route_v2,speakers_v2
```

Плагин возвращает выбранную версию и capabilities. `Legacy` продолжает использовать v1-команды. `Open` и `Keyed` требуют `radio_route_v2`; при отсутствии capability радио fail-closed, а direct voice продолжает работать.

Новый плагин понимает v1 и v2. После активации v2-миссии он не интерпретирует входящий v1 `TANGENT` как открытую передачу: такой клиент помечается несовместимым и его radio audio заглушается с явным предупреждением.

### 9.2 Route record

Каноническая запись:

```text
ROUTE = waveform,frequencyKHz,protectionCode,talkGroup
RX    = ROUTE,volume,stereo
LIST  = "-" | RX *(";" RX)
```

`waveform` ограничен ASCII slug `[A-Za-z0-9_.-]`, protection code — тремя цифрами, Talk Group — `0..9`. Разделители не допускаются внутри значений.

### 9.3 Команды

`FREQ` сохраняет прежние trailing-поля, но получает явную версию:

```text
FREQ\t2\t<sw-list>\t<lr-list>\t<dd-route>\t<alive>\t...
```

Передача:

```text
TANGENT\t2\tPRESSED|RELEASED\t<waveform>\t<frequencyKHz>\t<code>\t<tg>\t<range>\t<subtype>
TANGENT_LR\t2\tPRESSED|RELEASED\t<waveform>\t<frequencyKHz>\t<code>\t<tg>\t<range>\t<subtype>
```

Плагин добавляет nickname только при broadcast другим TeamSpeak-клиентам, как и сейчас. Speakers используют `SPEAKERS\t2\t...` и тот же `ROUTE`.

Parser обязан:

- проверять точное число полей, длины и диапазоны до изменения состояния;
- ограничивать число RX-records фактическим максимумом каналов/раций;
- отбрасывать запись целиком при ошибке, а не частично открывать маршрут;
- не падать на неизвестной версии/capability;
- логировать reason code без protection code в обычном логе;
- показывать несовместимость addon/plugin один раз, а не спамить каждый frame.

## 10. UI

Привычные PTT, numpad-каналы и открытие SW/LR-рации не меняются.

В каждом штатном radio dialog появляется поле `NET` рядом с частотой выбранного канала:

- `OPEN` для `000`;
- три цифры для `001..999`;
- read-only `OPEN` в режиме `Open`;
- скрыто либо read-only legacy label в `Legacy`;
- disabled при `TFAR_allowProtectionCodeProgramming = false`.

Ввод применяется по Enter тем же паттерном, что частота. Ошибка не закрывает dialog и не меняет старое значение. Переключение канала немедленно обновляет `NET`.

Действие `Copy network` добавляется в существующее меню выбора/копирования раций. Для радиоскинов, где мало места, кнопка может открывать один общий небольшой dialog; отдельная PTT или обязательная новая клавиша не добавляется.

## 11. Миграция старых миссий и preset-частот

1. `Legacy` остаётся default, поэтому обновление мода само по себе не меняет слышимость.
2. Новая версия плагина продолжает понимать старые `FREQ/TANGENT/SPEAKERS`.
3. Existing frequency arrays не меняют синтаксис и значения.
4. При первом чтении settings без schema v2 массивы `protectionCodes[]` и `talkGroups[]` дополняются лениво и записываются обратно в экземпляр.
5. В `Open` всем channel slots назначается `000`.
6. В `Keyed` новый per-channel preset имеет приоритет. Если его нет, каждый channel slot получает отображение текущего `legacyCode` через `TFAR_legacyProtectionCodeMap`.
7. Встроенная карта: `_bluefor → 100`, `_opfor → 200`, `_independent → 300`, пустой code → `000`.
8. Неизвестный непустой legacy code без mapping считается ошибкой конфигурации и блокирует radio route. Он не превращается в `000`.
9. `talkGroups[]` до #10 заполняется нулями.
10. Settings, клонированные при copy-loadout, получают независимые массивы (`+array`) и не разделяют последующие изменения.

Mission author может включить `Open/Keyed` только после обновления addon и TeamSpeak-плагина у всех игроков. Автоматического downgrade из новых режимов в `Legacy` нет.

## 12. Threat model

| Угроза | Результат/мера | Статус |
| --- | --- | --- |
| Две стороны случайно используют одну частоту | В `Keyed` не слышат друг друга без одинакового кода | Покрыто |
| Разные модели совместимых раций не связываются | Classname удалён из решения; проверяются capabilities | Покрыто |
| Захват настроенной рации | Компрометирует все коды, сохранённые в этом экземпляре | Намеренная механика |
| Копирование loadout создаёт связанную рацию | Создаётся snapshot с независимыми settings | Покрыто инвариантом |
| Перебор 999 кодов | Коды не считаются криптографией; сканер не входит в MVP | Вне модели |
| Чтение `missionNamespace`, памяти или pipe | Модифицированный клиент может увидеть route | Вне доверенной границы |
| Модифицированный TeamSpeak-плагин | Может проигнорировать routing/mute и слушать аудио | Вне доверенной границы |
| Сниффинг/запись TeamSpeak-аудио | Protection code не шифрует транспорт | Вне модели |
| Traffic analysis | Частота факта передачи и metadata не скрываются | Вне модели |
| Подмена mission setting клиентом | Сервер публикует политику; честный клиент применяет её | Частично; Arma client не trusted |
| Downgrade на v1 в `Keyed/Open` | Fail-closed, старый tangent не трактуется как open | Покрыто |
| Malformed protocol record | Строгий parser, limits, atomic reject | Покрыто |
| Радиопомехи/коллизии/jamming | Не моделируются в #9 | Отдельная задача |
| Relay между защищёнными сетями | Запрещён по умолчанию, только явный mission bridge | Будущий этап |

В документации и UI нельзя называть трёхзначный protection code настоящим шифрованием. Подходящее название для игрока — `NET code`/`код сети`.

## 13. Проверки перед включением режима

### Автоматические

- parser v1/v2, неизвестная версия и malformed records;
- нормализация `50`, `50.0`, `50.000` в `50000`;
- все строки матрицы совместимости как table-driven tests C++;
- границы диапазона и step mismatch;
- `000`, leading zeros и invalid codes;
- отсутствие fallback в open при ошибке;
- миграция settings разных длин;
- независимость массивов после copy-loadout;
- v2 speaker route и additional channel.

### Ручные multiplayer

- две одинаковые SW-рации у игрока и remote-controlled бота меняются независимо;
- захват SW и LR противника, чтение и ручной перенос network tuple;
- SW ↔ LR на 50 МГц и невозможность LR принять 100 МГц;
- `Legacy` A/B против текущего релиза;
- `Open` с разными прежними side codes;
- `Keyed` с совпадающим/разным/открытым кодом;
- смена кода и канала во время незажатой и зажатой tangent;
- main/additional channel;
- speaker radio;
- старый addon или plugin в v2-миссии даёт явную ошибку и не открытый эфир;
- respawn, drop/pickup, Arsenal/loadout copy и Zeus remote control.

## 14. Разбиение реализации после утверждения

После merge дизайна #9 следует закрыть и создать отдельные implementation issues:

1. **Protocol v2 и capability negotiation** — общий фундамент, dual parser и fail-closed version policy.
2. **Radio capabilities и settings schema v2** — waveform/band/step, per-channel code/TG, миграция и API.
3. **Routing Open/Keyed в TeamSpeak-плагине** — structured route, SW↔LR, tangent и speakers без изменения DSP.
4. **UI и capture programming** — поле `NET`, валидация и `Copy network`.
5. **Mission policy, diagnostics и compatibility tests** — server-enforced mode, reason codes и multiplayer matrix.

Первый deployable vertical slice должен включать пункты 1–3 вместе: хранение без plugin routing либо новый routing без version gate нельзя выпускать отдельно.
